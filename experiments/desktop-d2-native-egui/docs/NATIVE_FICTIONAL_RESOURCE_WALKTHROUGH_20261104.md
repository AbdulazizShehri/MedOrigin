## Actual user-facing function

The native MedOrigin Desktop now has a lightweight **session-only resource walkthrough** in the Workspace home, alongside the already source-verified Patient context, Encounter and Observation navigation. When an explicit reviewed ephemeral or persisted fictional Core readback is present, the top-level home shows **Fictional session walkthrough: 0 of 3 identities visited**, a **Open next unvisited fictional identity** button and **Reset fictional walkthrough (session only)**. Opening next follows a deterministic, nonclinical navigation sequence: **Patient → Encounter → Observation**. The selected resource offers an explicit **Mark fictional identity visited (demo only)** action, and the native home updates the 0/3, 1/3, 2/3, 3/3 count. When all three have been marked visited, pressing Next does not invent another record, but displays **All three fictional walkthrough steps complete (session only)**. Reset clears progress to 0/3 without altering the actual AES-GCM encrypted Workspace, modifying source identities, or creating a clinical review/audit entry.

This feature intentionally uses the term *visited* rather than *reviewed*, *signed*, *approved*, or *processed*. The fixed three check marks are only **Rust per-GUI-process in-memory UI state** (three booleans). They are not persisted in SQLite, OS keychain, clipboard, network, local files, database or Core. Changing the readback source, selecting a different D0 developer fixture, verifying another synthetic report, Escape or Clear forcibly resets the marks and source. Search and resource-type filters do **not** erase review state prematurely but a walkthrough jump clears stale search/type facets, relationship breadcrumbs and stale notice before selecting the source-derived next record. This path never pretends that a walkthrough jump is an authentic FHIR relationship edge. The previously verified patient-context graph and relationship navigation remains available.

Every mark, next and reset request independently rechecks the already-admitted **source-derived exact Patient/Observation/Encounter graph**, with verified audit/reopen claims and exactly 3 resources. A forged link, missing resource, duplicate type, stale selection or out-of-range index fails closed and clears the source and marks. The source itself remains limited to the two separately SHA256-pinned fictitious Core memory readback forms (ephemeral 1164 bytes and persistent 1215 bytes). No arbitrary input, raw FHIR, date inference, diagnoses, orders, terminology or clinical validation is introduced.
