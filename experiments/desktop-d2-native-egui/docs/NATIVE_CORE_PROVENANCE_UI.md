# Real native D2 Core provenance inspection panel — fictional, source-pinned, 2026-11-04

**An implemented and interactive D2 native UI feature, but deliberately NOT a live Python Core connection or clinical workspace. NO user files, EHR, PHI, signing, release, or external network.**

## What the D2 user can now actually do

Open the D2 native Rust/egui app on Windows, macOS or Linux, expand the **Core provenance: two fictional reports (NOT validated)** section just after the first four primary SHA selectors, choose either of two fictional Python Core QA reports, click **Inspect Core synthetic provenance (read-only)**, and see its independently reverified SHA-256 receipt, case classification, status `not_validated` and prominent `FHIR R4 NOT validated` disclosure. The first two preview-report datasets were obtained from **the real Python Core** using `medscale.fhirkit.validate.validate_fhir` and `medscale.fhirkit.report.report_to_json` in an isolated source QA checkout at commit `ad0c62b4366789f5c7e41fc601bb6d0f9d640873`, fixed timestamp `2026-10-24T00:00:00Z`. The Core source and inputs were already tested end-to-end under the macOS local process/network-denial QA in parent #904.

The reports are **small, immutable, compiled-in source bytes** in `fixtures/core/`. Their exact Core-produced canonical JSON and SHA are independently pinned:

Both contain exactly nine source-sorted canonical report fields with trailing LF, `status=not_validated`, one explicit warning, empty errors and `report_id=""`. The first represents provenance only, **not a completed R4 schema/profile/terminology check**. The second is an explicit negative control, not an allowed clinical resource.

`src/core_provenance.rs` now includes source bytes using Rust `include_bytes!` at compile time; `inspect_pinned_core_report(index)` reruns the existing strict 9-field parser, limits size, checks input-hash allowlist, warning, status, and SHA-256 of the **actual embedded bytes** before returning a compact non-sensitive receipt. Invalid indexes or changed source report bytes are refused. `src/app.rs` only displays this receipt, not the JSON source payload, and uses a separately selected report index. Any new fixture verification, selection, Escape or Clear invalidates stale receipt/UI state. New buttons and labels are after the original four selectors and Verify; prior UIA/AT-SPI/AX fixtures preserve order.
