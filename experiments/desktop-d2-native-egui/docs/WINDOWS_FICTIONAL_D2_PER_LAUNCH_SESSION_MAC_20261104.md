# D2 private Windows fictional Core per-launch HMAC session binding

**2026-11-04. Strictly private synthetic research preview, stacked above #940. No patient data, EHR, medical/release authorization, or production IPC claims.**

## Purpose and actual product behavior

PR #940 proves a real Windows desktop native GUI using source-attested installed pure-Python Core/Workspace in a portable development kit without Git/Wheels at runtime. It nevertheless sends the same reviewed 1,164-byte fictional decrypted Core projection to D2 on every launch. A static report cannot by itself identify a fresh process/launcher. This slice makes the **portable kit's default integrated GUI launch use a new opt-in per-launch integrity frame**, rather than the legacy static `--synthetic-encrypted-readback-stdin` path.

The trusted private Python launcher generates **new 16-byte random nonce and 32-byte random key on each GUI process start** using Python `secrets.token_bytes` (OS CSPRNG). It takes only the **actual fixed fictional AES-GCM Core import/reopen/readback result** (1164 bytes, SHA256 `c99af04367aeaedeecb29b7fccc8a8fb58f2a85753eeae874eae5ad363307a49`) and creates a bounded binary frame: `MedOrigin-D2-FICTIONAL-SESSION-V1\0` || nonce[16] || MAC[32] || original 1164-byte projection. MAC = HMAC-SHA256(key, domain || nonce || 32-bit big-endian original length || exact original projection). The session secrets are sent only to this GUI child via its **process environment**, never written to the kit's JSON manifest, Git, logging output, readback or encrypted store.

Native Rust D2 has a new explicit flag `--synthetic-encrypted-readback-session-stdin`, never used on normal unflagged app startup. Its finite 2048-byte/5-second stdin reader refuses missing/malformed key/nonce, incorrect domain, changed nonce, wrong MAC, tampered payload or unreviewed inner exact projection before constructing any GUI. HMAC verification uses the existing pinned sha2 0.11.1 (no new dependency or system API), constant-time aggregate byte difference, and RFC 2104 standard HMAC. The retained legacy static fixture flag remains for old source QA and deliberately **rejects a session-wrapped frame**; no silent fallback from a failed session. Crucially, the native GUI still executes no Python, filesystem, socket or browser workflow.

This is a **launcher-bound one-shot integrity control** and a meaningful rejection of passive static replay across fresh launches. It is **NOT production identity authentication**: the launcher chooses/passes its own environment key, processes with equivalent OS rights could inspect/replace environment/code, and replaying a frame with the same old key+nonce in an independently compromised context is not cryptographically excluded. No independent trusted challenge from D2, secure OS keystore, signed source identity, server, monotonic counter or OS-enforced egress restriction is claimed.
