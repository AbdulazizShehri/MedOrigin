## Added developer-facing behavior

The native, browser-free eframe D2 application now exposes an explicit **Inspect fictional JSON (verified, read-only)** action for nine approved source-compiled JSON byte sequences. It re-runs D0 raw SHA-256 plus limited fictional FHIR envelope checks, then verifies D0 response contract, fixture identity, byte length, exact previously pinned SHA, synthetic-only and release-denial flags **before** showing raw source text. The JSON is rendered as-is, with no parse/re-serialization that could silently repair duplicate or invalid semantics.

Only source-embedded `patient-minimal`, two `observation-*` and six `bundle-*` fixtures are allowed to produce text (all at most 2,048 raw bytes; actual examples max 559 bytes). The intentionally invalid UTF-8, exact 32,768-byte and 32,769-byte boundary examples are refused for JSON preview with a clear message while their synthetic SHA/envelope tests remain available. Unknown IDs and path/URL-shaped inputs fail closed. No clipboard, external data, remote request, arbitrary path, recording, telemetry or persistence is added.

If a new fixture is selected or verification repeats, previous preview and notice are cleared before any additional content can be displayed, including on verification failure. The original four primary selector UIA/AX/AT-SPI order and Verify control are preserved. The preview action follows the initially collapsed eight-case section, so existing test navigation keeps its original sequence.
